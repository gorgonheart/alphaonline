# 账户预选与 ready 等待实施计划

> 使用 executing-plans 原生执行，先本地验证，再部署 Ubuntu 测试机。

**目标**：调度器在等行情之前选好本轮账户。所有使用公共 ready 检查的账户，标记齐全后稳定等待 1 秒。

**范围**：以已确认的第一步为准。每轮读取账户当时的配置，沿用 offset 解析、默认 0m 和原账户顺序。不启动预热交易进程，不提前发交易所请求。上游 alpha 的发布时间不变。

1. [x] 为真实调度函数编写离线回归：同分钟多账户保持串行；未命中不收集垃圾；空分钟仍向 MODEL 协调器提供全部账户、跳过行情并补眠到目标时刻；缺 ready 不运行。覆盖传统和 MODEL 的公共等待、轮询和超时。
2. [x] 修改 `startup.py`：调度从提前休眠返回后，每个账户一次解析 offset；debug 从同一轮解析结果取得首个 offset。保留所有有效 offset 账户的 prepare；仅对命中账户等待、启动 worker 和提交统计。空轮调用既有补眠函数，避免在同一提前窗口反复运行。
3. [x] 修改 `core/utils/datatools.py` 的公共稳定等待；ready 检查仍要求同 stamp 文件齐全。MODEL 继续等两份 dict 和两份 pivot，传统路径沿用既有条件。
4. [x] 加入按 stamp、账户和毫秒墙钟关联的阶段日志。MODEL 在协调器观察到四个标记时记录，调度器在启动进程前记录，账户入口在准备账户前及准备成功后记录。已有 MODEL_REPLAY start 可再区分 MODEL 前置处理。记录的是程序观察时刻；无需读取 ready 文件 mtime。
5. [x] 本地 alpha311 先复现失败，再跑新增测试、现有退出码及调度回归。比较测试服业务文件与本轮修改前基线，有差异则只同步对应片段。所有服务器测试材料及回滚备份放在 alphatrade/test 下。
6. [x] 测试服隔离验证公共路径和同 offset 多账户，再检查 dry_run、活动 worker、启动清理范围，安全时重新加载测试交易调度器。核查空分钟与有账户分钟的日志，区分隔离验收和实际轮次。回滚仅恢复本次修改的文件并在空闲时重启测试调度器。

## 执行结果

- TDD：原版 5 个预期失败。复核发现错误 offset 会阻断其他账户，追加 1 个坏配置用例，验证唤醒后读配置及单账户隔离。最终本地 41 项、Ubuntu 41 项通过（同一组测试）。
- 运行代码共四处。startup 预选与派发日志；core/utils/datatools 公共等待；core/account_exec 只加两处计时；tools/robust40/server 记录实际观察到四个 ready 的时间。传统账户只经过公共 ready 门，不应寻找 four_ready 日志。
- Ubuntu 隔离验证使用已发布的 45m 和 25m 标记；传统账户实际公共等待 1.000 秒，MODEL 读取同轮 Arrow 表头。账户 API 和订单为替身，MODEL 快照资格为测试条件，不作为交易或整轮性能数据。
- 测试服后台 25m 重建进程退出后，14:38:48 仅重启 alphatrade-dryrun，PID 638081 → 850132。PM2 自然 14:40 空轮跳过行情等待。发布后首个自然 25m 轮次的四段耗时尚无样本。各阶段的 at 是 Unix 秒，观察精度毫秒。
- 测试、备份与回退位置：/home/ubuntu/alphatrade/test/offset-ready-mnCdjjvX/。回退时在测试交易进程空闲状态把 before 下四个相对路径恢复到 alphatrade，再重启该 PM2 服务。业务对这个目录没有依赖。
