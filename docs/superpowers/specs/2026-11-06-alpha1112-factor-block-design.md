# alpha 1.1.12 遗留与因子块优化设计

日期：2026-11-06。状态：待人工审核；本次仅形成设计和实施顺序，未修改运行逻辑或服务器。

## 目标与边界

将生产者 1.1.12 剩余功能、已发现的价量发布问题、交易端 FACTOR_BLOCKS 定位和优化纳入同一研发批次，但分别验证、分别发布。资金费率和历史起点修复视为已解决，仅作为回归约束。保留 C 长因子、Arrow 联动、空档补算、预热、分钟偏移、失败清理、传统策略和 MODEL 恢复语义。

用户已确认：现货／合约映射在离线副本修正完整保留历史，验证影响后单独安排发布。不是只改最新一行，也不是直接改生产 snapshot。当前最新代码存在大量未提交定制；不能整体复制 1.1.12 覆盖 core。

## 方案与选择依据

推荐逐项移植：先修行情正确性，再完成跨年与市值功能，最后在固定正确输入下优化因子阶段。每项均有独立失败测试、最小实现、对拍和成本统计。

整体升级基准包会覆盖现有资金费、起点、Arrow/C 和调度定制；同时改行情与计算链则难以分辨目标变化的来源，均不采用。本设计为推荐方案，尚不代表用户已批准全部细节。

## 行情正确性合同

### 映射

精确同名优先；剩余归一化分组仅一对一时配对；歧义保留未匹配，不凭排序选一个。沿用既有名称拆分规则，不额外调整价格/数量倍率。按原 `calc_match` 的双方有效时间交集重算保留历史映射，清除此前错误的对侧字段，不能只在新匹配范围内覆盖而遗留旧配对。

离线历史修正不宣称恢复未知的历史交易所规则。缺历史上市/更名证据时列出范围和限制；不得将现在存在的对侧合约强加到其上市前。产出受影响币、时间、选币和目标合约差异。已成交订单不追溯改写；切换可能触发 MODEL 回放或完整初始化，列入单独发布审核。

### 新币、空行情与重叠修正

取满请求窗口的第一根重采样可能截断；短历史新币的已闭合首根可以覆盖旧值。是否取满以过滤当前基础 K 线之前的返回数量判断。单币无数据、空分区、全空批次不崩溃、不伪造行情；其他有效币可继续。整个市场都缺当前有效行情时不得伪发公共 ready。

修正必须贯通 resample → raw batch → 全历史长因子 → Arrow → 年度 Pivot。保留历史起点和已结算 funding，不能从仅包含新行的 enrich 结果重置它们。对重叠时间戳按已确认来源覆盖价量，按受影响年份更新 Pivot；无变化时不额外重写旧年。

失败重试必须覆盖“batch 已写、Arrow/Pivot 未写”的情况。更新范围从当前可信源及已有成功 ready 推导，不能只比较已更新 batch 后认为没有变化，从而永远漏修 Pivot。不新增长期全量副本或独立历史台账。

成熟币问题另行采集最小证据：同币、同 offset、同闭合边界的原始 5m 响应及时间、重采样、batch/Arrow/Pivot。新币首根补丁不能作为成熟币末根修复完成的证明。没有获得稳定闭合数据前，不靠统一 sleep 或忽略差异掩盖问题。

### DataAPI 发布时机

消除“任一任务成功就立即预处理”的覆盖缺口，也消除预处理期间根据另一个源实时 ready 改变来源的竞态。推荐在本轮内存中确定每币来源，沿用 Binance 优先、DataAPI 兜底；覆盖通过后一次派发，同 stamp 公共 ready 后不可重写。

Binance 已覆盖有效市场时，不等待失败/超时的 DataAPI 才发布。DataAPI 先完成但缺币时等待缺失币的 Binance 结果；有交易对但尚未有 K 线与请求失败分开处理，后者不能冒充前者。若保留 DataAPI 全覆盖抢先路径，须固定整轮来源选择，验证它不会再次引入混源；否则先采用更简单的 Binance 完成后选择，记录等待成本。此分支取舍在 Task 5 复现后以证据落定，不改变来源优先级。

### 跨年与市值

上一年 Pivot 的完成条件为 UTC offset 网格最后一个合法 bar 已闭合且落盘；使用配置 bar 间隔，不用稀疏索引的最小间距猜周期。它只是年末边界完成，不代表所有币历史无缺口。复用 1.1.12 的每市场/年份 `.complete`，原子成功后写标记；标记存在但 Pivot 缺失时不能跳过，重建失败不能提前标完成。无修订时跳过旧年；合法价量/资金费修订仍可更新，跨年更名/新增列不得删除旧历史。

市值统一 `float64` 七列：usd_price、max_supply、circulating_supply、total_supply、max_mcap、circulating_mcap、total_mcap。下载和历史 CSV 导入同一约束；允许原格式缺失值，非法文本明确失败，保留旧有效文件和待导入 CSV，不默默填零。不顺带修改代理、认证、产品日期及去重优先级。

## FACTOR_BLOCKS 性能设计

先定位后选优化，不能预承诺追回 20 秒。共享入口覆盖初始化、续算、修订回放与正式交易的计算阶段；交易网络动作不参与性能实验。

1. 复用当前证据，按自然轮补充聚合计时：spawn/首结果、Arrow打开与读取/裁剪/转换、merge、外部因子数据、因子数值、pandas→Polars、父进程等待、concat/partition/write、退出及释放。worker 用 CPU 与墙钟分别统计；并行累计值不能与父阶段直接相加。
2. 同一机器、同一冻结输入及外部市值/BTC数据、同一父配置顺序，交替跑原版/候选；全量 Arrow 与其末 5000 副本先逐值确认共同尾部相同。生成副本、进程导入/创建、传输、写盘、回收全部计价。单独冷/热及忙时/空闲时，不在生产清页缓存。
3. 先全市场 4 worker 基准，定位后再小范围比较 3/4 worker、pending 与分片大小；不全排列、不默认加核。保持 `_row`、参数顺序、并列排名、BiasV1 删行/索引、资金费输入修改顺序。
4. 优先候选：worker 生命周期只读 Arrow reader/小型辅助输入复用、父配置一次传入、减少重复转换与实际热点因子的中间数组；均需测得收益才保留。不得缓存可变因子输入、跨轮沿用旧路径，必须有限句柄/内存并退出释放。跨进程复用不代替旧文件生命周期检查。
5. 有序任务消费可能有队首阻塞，但它同时限制结果驻留。只有测得长尾问题才考虑有限乱序收集并按原编号输出，不取消背压、不改变行序。块按 32 币写出与 2016 小时选币块是不同维度，不能混为同一个并发参数。
6. IPC 压缩、分块变化、GC仅作为证据支持后的实验，不默认重写为全Arrow、数据库或全局禁GC。一次只启用一个候选，输出和下游选币/仓位精确对拍。

## 范围、验收与部署

- 上游主要范围：symbol_match、binance_update、preprocess、realtime_data、必要的 data_api_update、coin_cap/quantclass_async；不替换整个 core。下游性能主要范围：select_coin、utils/factor_data、必要时 factor/相关单个因子。startup 不为因子优化修改。
- 新数学/逻辑先独立 oracle 失败测试再最小实现；修正类与旧错误结果允许有明确解释的差异，性能类必须在相同输入/状态下严格一致。缺失值、dtype、行索引/顺序、选择、S3、模型、正负权重、固定执行输入的手数均检查。
- 初始化、普通续算、修订回放、正式交易计算四场景；另覆盖 12 个5分钟 offset 的边界单元、跨年/停机、传统45m代表策略。12 offset 单测不等于12账户自然运行通过。
- 峰值内存、swap、输出字节和清理耗时与端到端耗时一起记录；不只报函数内计时。无新全盘扫描、无额外hash/manifest体系。测试文件只在可删除 test/，有效状态不复制成长期研究包。
- 已有后半程优化补验：新进程 JIT、再择时全结果、Arrow全/短/重新全量联动、超范围后台重建、传统策略、实际执行分段观测。真实订单只观察获授权的自然运行，禁止为验收额外下单。
- 本轮计划不等于部署授权。正式发布独立审批；映射与价量修正分批发布，保留对应代码和可用状态，不把文件回滚等同撤销订单。
