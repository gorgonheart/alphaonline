# 正常轮次修订输入读取优化

本轮仅修改 `tools/robust40/handoff.py` 的读取/整理/比较实现，另加测试和离线基准。core、startup.py、sections、live.py、账户配置和alpha均无本轮修改。不启动或重启实盘，不改生产数据。

## 改动与边界

1. 正常Arrow检查在原有逐币裁行裁列后直接建立UTC索引和first_candle_time，复用该DataFrame；不再进入input_frames重复转换时间、切片、选列、复制和排序。小批次转pandas使用use_threads=False，避免逐币分派列转换线程。原read_arrow_tail默认返回格式保留，新增indexed参数只用于此路径。
2. Pivot仍逐个读取既有PKL，但先裁监控区间/字段再合并；不再将整段140xx历史拼成大表再切168小时。底层PKL仍需完整反序列化，没有伪称只从磁盘读取168行。
3. 比较新旧时间轴只定位一次，用同一位置数组取行；完全相同的时间轴直接比较。缺历史仍拒绝、真实数值差异仍检测，不增加容差。
4. 保存输入时每张表只裁一次；原实现字典推导式在判断非空和取值时各裁一次。

初始化/full PKL及调用方显式提供raw_swap的原路径保留。正常持久化仍为最近168小时；读取起点仍取上轮保存输入的最早时间，停机后可读超过168小时，不缩小历史覆盖。价格/成交量/交易资格/映射等监控字段、共同恢复点、重建/训练规则均不变。没有新缓存、额外校验文件或跨账户/跨轮共享状态，也没有让新旧行情混用。

这次消除了检测内部的重复转换与全历史拼接，没有改造框架选币/子策略/MODEL各自的完整行情读取。跨阶段共享完整Pivot会使其提前驻留并跨过并行选币阶段，可能增加峰值内存，需要另行测量后决定，不在本轮引入。

## 验证

TDD先用禁止调用全量Pivot/重复input_frames的测试复现失败。新旧输入逐值对照覆盖5/15/20/40/55偏移、168小时常规与410小时读取范围、UTC索引、类别字段、分片Pivot以及截止后的数据裁剪；重复时间仍拒绝。新专项与既有日志18项通过，既有修订/Arrow网格/失败路由15项通过。未修改因子数学，因此不增加新的因子golden。

真实40m交替基准在 `research/input_read_optimization/benchmark.py`，原实现快照为同目录handoff_before.py。检查新旧1276张输入表的索引、dtype和值严格相等，并核对完整PKL与Arrow基础输入；记录publication及运行前后输入文件大小/mtime，若上游在测试过程中变化则拒绝把本次结果当作有效对拍。仅写research，不复制或修改上游。

耗时记录见同目录result.json。范围是读取、比较、末尾裁剪和内存序列化；不包含旧输入反序列化、文件写入、模型/交易流程。历史4.95秒只作为前次参考，不能与不同机器负载下的本次读数直接计算提速；应以本次交替新旧测量为准。线上收益继续用MODEL_REPLAY的input_read_s、compare_s、prepare_s观察。

实际结果：publication=1793443200，169小时读取（上轮168小时加新一根）、1276张表，全表check_exact=True通过，完整PKL/Arrow输入比较无差异，测试前后上游文件大小/mtime未变。

| 中位数（3轮交替） | 原实现 | 优化后 |
|---|---:|---:|
| 读取与整理 | 20.720秒 | 6.041秒 |
| 比较 | 5.426秒 | 1.433秒 |
| 裁剪 | 5.390秒 | 0.603秒 |
| 读取+比较+裁剪+内存序列化总计 | 43.287秒 | 8.375秒 |

机器负载波动明显：旧读取13.43–39.01秒，新读取5.52–26.55秒；序列化本身未改也有显著波动，不能把总计下降全部归因于代码或承诺固定提速比例。本次结果支持消除重复处理，但不代表稳定P95。线上由下一批worker的现有日志继续统计，无需调整配置或重建snapshot。
