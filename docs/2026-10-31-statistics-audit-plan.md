第一阶段已按后续指令本地实施，当前行为、验证及待人工复核项以[实施复核](2026-10-31-statistics-phase1-review.md)为准。本文保留原审计发现和分阶段计划；第二阶段未实施。

日期：2026-10-31（香港时间）。状态：**审计及计划，尚未修改业务代码，待人工复核后实施**。

范围：本地core/utils/statistics.py、statis_func.py，直接关联的startup调度、账户概览和成交适配接口。已复查两端Git差异；不改alpha，不排查此前已说明解决的alphatradetest依赖部署问题，不登录服务器、不查私有账户、不发送通知。保留现有未提交修改。

## 结论

现状的主要成本来自多余网络查询、全历史成交扫描、重复读文件和重复绘图；先去掉这些工作，比增加线程收益更确定。现货金额和盈亏则存在独立的正确性缺陷，不能靠加缓存、扩大recvWindow或换回第三方原版解决。

推荐分两阶段：第一阶段修正统计入口、快照和展示口径，停止误报且减少请求；第二阶段补齐原始成交身份、分页与费用处理后，才恢复可信历史成本和实际成交盈亏。不在统计热路径中自动重建多年历史。第一阶段明确显示未知值，不能把暂缺数据替换成0收益。

## 发现与证据

### P1：金额、盈亏及历史状态可能错误

1. **现货市值与历史净投入混用，数量没有对账。** statis_func.py:48–101会原地修改输入，并将CSV“持仓额”改名pos_u，历史为空才用实时市值。ETH本轮重跑原复现脚本，实际run()调用链仍显示数量0.6295、金额22472.69、盈亏-8895.61；实时数量0.6294843×2407.22应为1515.31。历史数量5.6401513，差额5.010667的来源仍未知。不得推测为某次清仓或划转，也不能按比例缩放旧账本当作已对账。

2. **账本“持仓额”不一定是剩余持仓成本。** statistics.py:173–276用累计买入额减累计卖出收入计算，卖出收入包含已实现收益，结果可为负。即使数量匹配，也不足以证明它是可信的剩余成本。例如买10×100、卖5×150，剩5，当前方法净投入250、均价50；加权剩余成本应为500、均价100（暂不计费）。因此修复不能只将历史列改名“成本”并继续按它展示未实现盈亏。

3. **手续费记账错误。** statistics.py:186–189对基础币手续费统一qty-commission，并同比缩小quoteQty。离线复现买1 ETH、支出100U、扣0.01 ETH手续费，记录数量0.99正确，但净投入被写成99而不是100。若卖出也收基础币手续费，实际数量变化应为-(qty+fee)，现公式却为-(qty-fee)。BNB及计价币手续费还需分币种处理，不能一律用被交易币的现价换算；应明确费用与成本口径。

4. **成交增量可能漏记，重建可能丢失重新开仓。** statistics.py:241按聚合后的小时严格“大于旧末行”截取，晚到同小时成交被丢弃。:263–266只要任何中间行低于5U就删整个文件并返回：本地复现原仓1，卖1清仓后再买2，最终文件被删除，2的新仓未记录。按当前价格决定历史清仓，也会让历史解释随行情改变。应以真实数量和交易精度判定，不以现价5U清理历史。

5. **分页先丢精度，再按1000条判断完整性。** statistics.py:95–105先把真实成交时间聚合到offset；get_orders:142–157再按该时间删除最早一组并往前翻页。1000笔都在同一分组时，离线复现No objects to concatenate；同一小时交易密集时不能证明没有遗漏。Binance base_client.py:1292–1323又丢掉trade ID，并将查询失败变为空表。OKX对应接口每页100条，而statistics硬编码1000判定，不能视为通用分页。第一阶段不要把这些结果宣称为完整历史。

6. **1h/24h不一定真有相应历史。** statis_func.py:309使用当前墙钟而非本轮统一观察时刻；:325历史不足直接取最早数据。离线仅有1小时前记录仍返回为24h基线。当前持仓整体为空时，:352直接返回空，全部清仓的币种反而消失。缺价格也会算成0，而不是未知。

7. **“持仓盈亏报告”实际是固定历史仓位的价格变动估算。** statis_func.py:439–452计算abs(历史pos_u)×价格涨跌，trade_pnl固定0；不处理区间加减仓、实际平仓、费用、资金费或资金流。现货历史pos_u又可能是成本，导致估算额进一步错误。“与账户净值差额略有偏差”的文案不成立，偏差可以很大。应改名为“历史仓位价格影响估算”，或在真实成交流水完整前停用该报告；不得作为真实账户盈亏。statistic.py:1027附近的“最近1小时盈亏”也是两次资产差，未剔除外部净流入，应改为“账户权益变化”，另列可核对的资金流。

8. **时间与历史数据不兼容。** statistics.py:611及statis_func.py:643的datetime.utcnow().timestamp()在本机按本地时区解释，实测epoch少28800秒。orders()仅用minute<offset+30分组，40/45/55m跨小时错误：00:05被归到00:40/45/55，按其现有“最近offset”意图应为前一日23:40/45/55。账户曲线又在:712统一floor('H')，抹掉分钟标签。原始成交时间必须保留，运行归属单列；不能用图表分组时间分页或去重。无参数批量run也会在首账户设置run_time后复用于后续账户，需每账户独立派生。

9. **展示精度被持久化，可能反过来污染计算。** calc_spot_position/calc_swap_position先将数量及价格round(4)，之后save_position_snapshot又将该表当作历史数据保存。低价币或微小持仓会变成0。历史量价必须保留原精度，只在发送副本上格式化。不能把新市值口径直接与旧cost口径pos_u混合计算；旧文件保留，无法无损恢复的数据标记不可用于估算。

### P1/P2：不必要请求、任务污染和失败处理

10. **非目标账户先请求，目标账户请求两次。** statistics.py:1258–1267先init_system→update_account_info，再比较account_param；命中后再get_account_overview。当前N个账户，每个定向统计任务最多N+1次overview（并非单个HTTP），3账户为4次，12账户为13次。若N账户每小时各触发一次，数量是N×(N+1)，而应接近N。overview结果跨时点混用，total_equity还用update_account_info扣除BNB预留后的字段，报表分母与真实权益并不一致。

11. **统计入口并非绝对只读。** AccountConfig.update_account_info的if_transfer_bnb分支（account_config.py:328附近）不受is_operate控制，统计调用也可能触发碎币转换。当前MODEL配置关闭该分支，但其他策略未必。最小方案是在statistics内仅调用一次bn.get_account_overview，构建统计所需字段，不复用交易账户更新动作；不改全局BNB补币规则。真实账户接口失败则本轮缺数据，不能使用默认0或旧值继续冒充成功。

12. **失败后扩大查询，且关键持久化过晚。** statistics.py:1335–1347把文件读取、网络查询、转换异常包在同一个try，任一异常都会回退全币池历史扫描；历史成交从固定2023起点反复拉取，有成交的每页固定sleep(3)。:991–1055又先查询划转、绘图、通知、查UniMMR，最后才写equity.csv；可选图表/API故障可能使成功获取的净值丢失。应先落盘基础事实，再独立执行各可选报告；缺文件、无交易、接口失败、缺历史必须区分。

13. **并发任务共用图片，历史写入没有幂等与互斥。** startup.py:66默认线程池并发启动统计子进程，statistics.py:912和statis_func.py:707全部用data/pos.png，多账户可覆盖/错发图片。历史PKL为读-改-写，CSV多处append，重复同轮或同账户任务重叠可丢记录/重复。尾部sleep(60)发生在本轮API及发送之后，对本轮突发请求不起保护作用，反而长期占用线程。风险由代码确认，本轮未实际发送图片复现错发。

14. **重复读写与展示边界。** 14子策略的资金曲线在All/30d/7d各读一次，最多42次可降为14次；策略归属及现货账本被持仓图、盈亏图重复读取，1h/24h各读一遍同一历史PKL；主净值曲线逐段plot，颜色实际恒定，可一次plot。未知/损坏数据不能由compute_recent_volume的(0,0)返回伪装为无成交；择时报告iloc[-2]需要覆盖只有0/1行、轮动因子下划线命名等边界。

## 建议口径

| 数据 | 定义/行为 |
| --- | --- |
| 当前数量、当前市值 | 来自同一轮账户快照及对应价格；现货市值=未舍入数量×价格。缺价格标记未知，不写0。 |
| 历史净投入 | 旧CSV累计买卖净额，仅作为审计参考；不得自动称为剩余成本。 |
| 可信成本、均价、未实现盈亏 | 需要完整事件与正确费用处理。数量不匹配时必须空；数量匹配只是必要条件，不能代替历史完整性。 |
| 对账状态 | 使用行级状态/原因（数量不符、历史缺失、费用待确认等），不增加checksum、registry或额外门禁体系。 |
| 1h/24h价格影响 | 指明按期初仓位不交易的估算；必须有合格时点和价格，全部清仓也应覆盖历史币种。无足够历史则“不足24h”，非0收益。 |
| 真实期间盈亏 | 完整成交、费用、资金费、外部划转等核对后另算，不冒用当前估算列。 |
| 时刻 | 记录运行归属run_time与实际observed_at；epoch用带时区UTC。观察跨多接口并非交易所原子快照，报告不能宣称精确同毫秒。 |

已保存的历史pos_u不能整体按新语义解释；建议新快照保留完整量价并显式market_value字段，读旧记录时标记来源与精度限制，不能仅凭旧四舍五入量价“修好”旧盈亏。首次生成新格式不会删除旧CSV/PKL，也不触发全历史重算。

## 分阶段开发计划与最小范围

### 第一阶段：减少请求、阻止误报

1. **statistics.py入口定向筛选。** account_param按现有文件stem契约先筛文件，再init_system；初始化后核对identity及offset，之后才进行API。仅目标账户创建客户端。移除统计中的update_account_info，一次get_account_overview供本轮使用，正确区分原始权益、交易预留与spot启用状态。BNB交易流程不改。
2. **统计分级。** 建议独立enabled和明细/图表开关；先提供基础余额、持仓市值、本地策略权重，成本未核对则空。历史成交、划转图、1h/24h估算及通知均为可选任务。可选任务失败不扩大查询、不抹掉已保存事实、不影响交易。全部统计关闭不影响必要交易查询，也不通过is_debug开关实现。
3. **statis_func.py数据与展示分离。** 输入先copy；市值统一、原精度保存、对账不通过时隐藏均价/盈亏；时间戳、历史不足、全平仓逻辑修正。历史估算改名并由调用方显式传入本轮观察时刻；窗口基线必须<=目标时间，设置允许偏差并展示实际区间，不再无条件向未来取最早记录。
4. **持久化先于通知。** 单轮核心记录按(account,run_time)更新，绘图或网络发送失败不影响已落盘数据。只对原有文件采用同目录临时文件+replace；同账户互斥或去重先解决，atomic replace本身不能防止并发覆盖。
5. **startup.py仅动统计调度。** 一个账户最多一个运行中任务；在途重复任务跳过并记录，不堆积旧任务。设置小的全局统计并发上限（先2，实测再调），不改变交易串行循环/分钟调度。明确读取subprocess失败，避免Future异常无人查看。不同账户仍独立。
6. **图片改为本次任务独有路径。** 账户/轮次/报告类型及唯一临时文件隔离，发送后清理自身临时图，避免data/pos.png竞争。只改统计图相关调用，不改公用通知实现。
7. **一次读取、多处复用。** 单轮加载现货/合约历史各一次、策略映射一次、每子策略资金曲线一次。价格按需求批量查询，不逐币请求。overview内部价格请求另计，不为追求“总计一次ticker”扩大修改所有交易所客户端；同一统计阶段额外ticker至多一次/市场，能由已取快照覆盖时不再查询。

第一阶段最小修改清单（实施前逐项人工复核）：

| 文件 | 边界 |
| --- | --- |
| core/utils/statistics.py | 账户/offset先筛选、一次概览、分阶段失败处理、落盘与绘图顺序、缓存、时间及图片路径。保留原入口CLI。 |
| core/utils/statis_func.py | 量价/成本状态、估算口径、历史时间、纯展示副本、独立图片路径及现有快照写入。该文件也被交易前snapshot调用，必须做回归。 |

### 第二阶段：可核对的成交增量及成本

1. 成交保留原始毫秒时间、trade ID、交易所/账户/市场身份；分页按交易所真实契约和原始游标，之后再按offset分组展示。兼容同毫秒多笔、满页与晚到成交、跨日，不把原始时间变成小时后再分页。
2. 在既有成交存储上增量读取/去重，起点采用已有可靠记录+小重叠窗口；没有可靠记录则显示待补历史，重建由独立离线工具显式执行。不得缺文件即全币池追溯2023。已存本地订单回执可用于本轮成交统计，但它不能覆盖人工成交/划转，也不必然等同完整fill流水。
3. 账本按真实事件顺序更新，区分买卖和手续费资产；清仓后同批新开仓继续处理。不按现价5U删除历史，不丢同小时迟到成交。将净投入与剩余成本明确分开，若采用加权平均必须作为新口径验收，不能暗中改变旧列含义。
4. 明确“无成交”和“接口失败/历史不完整”，后者停止更新可信成本，不写伪零。未知5.010667 ETH仍需划转/人工交易来源对账；本阶段代码无法自动补造缺失事件。
5. 额外core候选仅Binance/OKX的fetch_spot_trades：原始ID、分页信息和严格错误语义的向后兼容选项。原调用默认行为保留；不能只改Binance然后宣称统计框架已通用。若新增独立成交读取方法更小、更隔离，则优先新方法，由statistics显式调用。具体行数需接口设计完成后出diff审核，不预先承诺两行能解决。

- ETH三组既有样本：原账本/无账本/数量一致对照；最终市值均为1515.31，未知成本不展示虚假均价及盈亏，输入DataFrame不被修改。
- 同时覆盖数量一致但部分卖出净投入不等于剩余成本；基础币/USDT/BNB手续费、退款/负手续费、划转缺口等不能靠数量匹配一项放行。
- 全部0/5/10/…/55偏移，包括指定的5/15/20/25/45旧策略；跨小时跨日、晚计算、晚成交、分页满页、同毫秒多笔、同小时补记。
- 1h/24h历史不足、空仓与全清仓、缺价格、重复同轮、旧格式精度不足：不偷用未来快照、不伪报0或完整24h。
- 定向运行只查一次目标账户；零资金也能报告，不能沿用上轮字段；统计期间交易写接口全部禁止，if_transfer_bnb=True也不能换币，不影响正常交易自动补BNB。
