# alpha 1.1.12 与因子块：实施及验收记录

本轮在现有研发分支本地实施，保留两仓此前未提交依赖。未部署、重启生产者或交易服务，未修改账户、交易模式、生产行情或订单。Ubuntu 仅在测试机 `alphatrade/test/` 运行禁止网络的隔离测量。设计及计划已获用户确认，以下按实际证据区分实现与验收。

## 本轮实现

| 项目 | 实现与限制 |
| --- | --- |
| 现货/合约映射 | 精确同名优先，归一化剩余组仅一对一配对；完整保留历史重新赋值，清除失效对侧；缺对侧行情不伪造配对。真实账户历史选币及目标影响仍须离线验收，单独发布。 |
| 新币首根 | 以过滤当前基础K线之前的返回数量判定窗口是否取满；短历史首个闭合小时可覆盖旧部分值。 |
| 空行情 | 空分区、空年份安全处理；有交易对但暂无K线不阻塞其他币；整个市场没有当前行情不发布公共ready。真实空文件也视作无历史，成熟币缺失仍拒绝。 |
| 价量修订 | 同时间戳覆盖可信来源的OHLCV及派生字段，重算长因子并发布Arrow；Pivot按实际存在的币/时间单元更新。batch已写而Pivot失败后重试仍修正；保留历史起点、已结算资金费、旧币和旧年历史。 |
| DataAPI覆盖 | 等Binance任务完成后固定每币来源，Binance优先、DataAPI兜底；完整Binance可直接派发预处理，不等DataAPI。单源future异常不丢弃另一来源和基础5m更新；缺市场覆盖不发布。 |
| 年度Pivot | 已闭合年末网格且Pivot存在才写`.complete`；使用配置周期的UTC epoch网格，覆盖1h十二offset及2h/85m。价量修订在raw写入前撤销相应完成标记，资金费修订仍穿透。 |
| 市值类型 | 两个CSV入口统一七列float64；允许NA，非法文本抛错、不静默coerce。保留独立代理开关，默认关闭；不调整策略参数。 |
| 因子性能 | 市值倍率候选保留逐值标量`np.log10`，统一取整、每个唯一指数只求一次幂。精确对拍通过，但完整成本未改善，已从运行代码撤回，仅保留实验及oracle。 |

确定来源会牺牲DataAPI先完成时的抢先发布机会，这是为了消除同轮动态混源。这里的“不等待DataAPI”指预处理派发；进程池退出和本轮后续收尾仍可能等未完成任务，不宣称整轮完全不受API超时影响。

## 完整保留历史的映射影响

测试机25m原始批次就地只读审计，读取前后文件大小/修改时间不变；仅保留差异摘要，没有改写行情。按当前交易对及保留数据的双方时间交集重算：

| 序列 | 保留行数 | 映射变化行数 | 变化范围（UTC） |
| --- | ---: | ---: | --- |
| 现货1000CATUSDT | 14071 | 14071 | 2025-03-29 18:25—2026-11-06 00:25 |
| 合约1000CATUSDT | 14071 | 0 | 无变化 |
| 合约CATUSDT | 3041 | 3041 | 2026-07-02 08:25—2026-11-06 00:25 |

现货对侧由空值/CATUSDT修正为同名1000CATUSDT；CATUSDT不再错误指向该现货。使用实际`transfer_swap`，假设该现货每小时均被选中：3041行目标币名改变，11030行交易场所由现货变为合约，13358行成交参考价格改变。这是输入映射及转换的影响上界样本，**不是实际账户选币、仓位或历史订单结果**。真实账户哪些小时会选中、S3/仓管如何传导仍须独立验收，不能因当前未持仓而直接上线。

## 成熟币差异的证据

对2026-11-06 01:25 UTC轮，服务端就地检查BTC、OP、PUMP最近两小时基础5m及发布产物：

- 两端基础5m独立重采样均与已保存的Binance小时resample相同。
- resample→当轮Arrow：两端BTC、OP各有一行close/volume/quote_volume/trade_num不同；测试PUMP也不同，正式PUMP相同。
- 已定位“持久化源正确、发布缓存未跟进”这一分歧层，本轮重叠修订传播修复覆盖它。
- 没有保存初次HTTP响应及当时请求/返回时刻，不能据此声称已证明最早采集为何得到旧值，也不能声称自然下一轮已验证候选。

生产原始行情导出曾被自动审批拒绝；没有绕过，改为服务端就地比较，只返回聚合差异。没有增加长期行情采集。

| --- | ---: | ---: |

普通轮增加约0.701s/本样本，原因是必须比较和更新重叠历史；旧路径只追加新时间戳，虽快但漏修订。普通未修订输入的所有年度Pivot逐值相同。释放自有工作目录约0.05–0.07s。该样本不能线性推成Ubuntu全市场耗时；上线前须观察真实发布延迟。

## 因子块测量口径

测试机固定同轮spot/swap Arrow及市值/BTC输入，4个spawn worker、最多8个pending、32币写块、2016小时块。发布全集按账户币种过滤为1258个任务、4,526,887行，比自然轮交易币集合更大，不能直接替代此前88.946/68.1415秒的两机样本。

初始定位轮完整因子阶段111.58s；worker累计Arrow读取1.04s，pandas转换10.06s，外部数据53.40s，pandas→Polars29.30s；父进程写块18.98s。worker累计值有并行重叠，外部数据嵌套在因子耗时内，不能相加当墙钟。

市值因子CPU约29.83核秒，是明确热点；Arrow reader本身占比很小，不支持把20.8045秒差距全部归于14070与5000发布长度。两机完整差距尚未被精确分摊。未新增永久逐币埋点、提高并发、改变GC或重写因子内核。

1258任务旧新完整因子输出（含列、顺序、dtype及缺失值）逐值精确对拍通过。该检查每个币使用同一个父配置和冻结外部输入；自然两机运行不是性能oracle。

固定`PYTHONHASHSEED=0`控制父配置中集合派生列顺序，三组交替测量如下。完整进程耗时包含导入、生成配置、进程池、计算、传输、约3.05GB写块、删除块及退出；不计重复创建冻结行情副本，因为两版共用同一只读输入。

| 组 | 原版完整进程 | 候选完整进程 | 原版阶段含释放 | 候选阶段含释放 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 109.657s | 98.847s | 107.282s | 95.075s |
| 2 | 102.678s | 107.477s | 100.325s | 105.146s |
| 3 | 99.943s | 134.619s | 97.402s | 132.281s |
| 中位 | 102.678s | 107.477s | 100.325s | 105.146s |

市值部分CPU中位29.347→19.485核秒，所有worker CPU中位302.311→295.462核秒；但完整时间没有重复改善。父写入约16.63–22.41秒，存在同机运行波动，不能据此断言候选数学导致退化，也不能只挑第一组称提速。**按计划不接受该候选，运行代码已撤回**。不继续扩大并发或复杂缓存来追求不确定收益。

进程树RSS峰值约1.65–1.67GiB，候选中位约增加4MiB；这不包含所有文件页缓存，也不是初始化cgroup的MemoryHigh验收。未获得每组可归因的swap/PSI，不能宣称忙时资源预算全部通过。释放因子块约0.17–0.56秒。三个样本不提供P95。原始小报告见`test/alpha1112/server-reports/`，先前未固定随机种子的样本仅保留作探索，不与这三组混算。

## 发布顺序与仍需验收

1. 上游正确性补丁先在测试线单独发布，观察自然新币/双源失败/修订传播及发布延迟；部署、重启另行授权。
2. 映射修正单独批次：完整保留历史离线修正，输出受影响时间、选币、目标合约和模型状态影响，再人工审核。当前名称匹配不代表还原未知历史更名规则。
3. 若历史修订超过共同恢复点，沿用已批准后台初始化，成功后下一合法offset交易。回滚代码不撤销已成交订单，不盲目回滚已提交状态。
4. 本次因子候选不进入发布包。后续若继续优化，先在低噪声同机窗口定位计算以外的成本，再评估小型辅助数据复用；不把本次CPU减少折算成承诺收益。

## 磁盘与回收

运行新增持久文件只有每市场/年份一个小`.complete`，无行情备份库、hash清单或常驻缓存。来源映射只在本轮内存传给预处理。

测量工作区全部位于测试机`alphatrade/test/factor-profile-o0f2084q`，输入Arrow用硬链接固定、市值/BTC单份只读副本；每轮约3.05GB因子块在该轮结束后释放。17份JSON小报告已下载、逐份解析且核对源文件大小；确认无活跃隔离worker和精确目录归属后，整个自有工作区已删除，耗时0.064秒。该时间点磁盘空闲增加约114MiB，不把硬链接逻辑大小误报为实际释放量。业务、snapshot及其他测试目录未动。

本地23个已结束pytest临时目录释放169.13MiB，枚举及删除共6.283秒；后续撤回验证临时目录也单独释放。基线源码、窄补丁、复现脚本、测试日志和小报告保留在`test/alpha1112/`，没有业务运行依赖。
