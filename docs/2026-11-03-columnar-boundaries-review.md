# 当前 MODEL 的列式边界与数组交接审计

本轮范围：审计当前计算至选币、模拟至仓管及执行接口；另将当前账户涉及的旧时序因子增加 `signal_multi_params()`。本文的架构建议尚未实施，不代表批准重写 core、S3、模拟器或下单流程。仅本地离线工作，未操作 alpha/alpha2 或交易服务。

## 已确认的实际范围

对本地 `accounts/20m_robust_4h.py`、`40m_robust_4h.py`、`55m_robust_4h.py` 的 `strategy_pool` 表达式分别做隔离求值（不执行账户模块或读取密钥）：每个账户均为14组合、43策略；全部 `use_custom_func=False`、`select_mode=standard`，持有期为1H/4H/16H/24H/48H，没有日频。

四个截面为 `TopKTo2K`、`VolumeMaxBias_进出场阈值分离官方`、`动态回撤阈值`、`固定回撤阈值触发币数占比开仓门槛`。S5再择时为 `Bolling2multi`，S14为 `HGCappedBolling1022`。配置和参数本轮不改。

17个旧因子迁移范围：16个子策略及截面底层依赖，另加父仓管 `Bias`。父仓管的 `process_equities()` 当前仍逐因子参数调用，因此增加批量接口不等于其48/144/216三个窗口已合并为一次调用。

### 框架其他策略的边界

当前MODEL没有启用，不代表框架可删除：

- `use_custom_func=True`：自定义计算、前过滤、后过滤当前通过pandas回调。任意用户Python回调不能自动证明可用Polars替代；保留明确的局部适配入口，或逐策略单独移植。
- `entry_exit`：已有Polars评分，但持仓、补位、冷却、延迟和最大持有期依赖Numba/续算状态；不能拿标准选币的独立时间块处理。
- `after_merge_index`：策略可改行、补列或改变日频聚合定义。当前本地不存在strategy实现目录，配置使用抽象默认逻辑；不代表外部部署/后续策略不存在回调。
- 日频：`trans_period_for_day()` 的OHLC/成交量/映射聚合和后续23H执行移位必须保留，不能把日频当作较大的小时块。

结论：没有理由要求所有数据持续使用pandas，但存在无法省略的有状态计算与回调边界。列式主流程和少量原生数组/旧接口适配可以共存，不引入一套新的策略配置。

## 数组交接后还必须调整的接口

裸数组缺少时间、币种和市场语义，不能直接替换DataFrame。建议共享标签（时间轴、市场/币种轴、offset、共同截止）及数组引用；不新增文件注册表或哈希协议。

| 接口 | 必要改造 | 应保留的逻辑 |
| --- | --- | --- |
| 选币→聚合 | 长表直接构造目标数组，减少pivot→rolling→stack→pivot；现有v2仅候选 | 持有期、方向、组合权重、空窗、日频移位、现货转合约前snapshot语义；浮点累加顺序独立对拍 |
| `calc_equity` | 分离市场索引准备与数值模拟；state0/state1复用已准备行情；数组输入直接进入现有Numba核 | 交易单位、费用、资金费率、现有执行价格口径、持仓状态及checkpoint；不能借格式改造统一不同价格字段 |
| `process_equities` | 接收曲线数组和标签，减少历史仓位重复读盘；小曲线在必要边界转pandas | 资金曲线按hour_offset重采样、首尾不完整周期、父Bias、ffill/dropna及所有子策略共同时间范围 |
| 再择时 | state0曲线内存交接；只在Series信号入口包装小对象 | S5/S14必须用未择时曲线计算，再执行state1；杠杆只应用一次 |
| MODEL `build_context` | 已知时间/币种轴直接对齐数组并按需要转CSR，减少frame.loc/reindex和大宽表共存 | spot/swap区分、币种标准化、新币/下架币、单位变化；虚拟账户不能拿真实账户替代 |
| MODEL目标与模拟 | `portfolio_targets`目前CSR→dense DataFrame，`simulate`再取NumPy；可直接交dense数组，减少中间包装及可能复制 | 不能假设to_numpy总会复制；先测真实分配。9专家账户/最终账户及恢复点仍要计算，不能只保留末行 |
| MODEL风险/季度计算 | 保留小型日级/季度pandas分析，重用映射索引 | decision_days、完整24小时、beta时移、S5减仓、季度样本窗口不是单纯数组shape对齐 |
| 仓管→最终权重 | `calc_ratios`/`agg_pos_ratio`/仓位限制可用数组输入加标签适配 | 动态杠杆、父权重生效时点、平滑、限仓填充、S5变换及现有目标对照；不能直接删除两条路径对照而无替代验证 |
| 最终权重→目标手数 | 可直接传递权重，取消写PKL后立即重读；保留文件作为输出 | 实时账户/价格/规则刷新、目标币种与现有持仓并集、补BNB、权益口径、执行cap/死区、舍入、最小下单额和下单顺序 |
| 保存与恢复 | 在编排边界序列化既有状态，未来确需换schema再独立设计 | 当前S3/子模拟/MODEL共同截止与恢复点、计算已保存≠订单已成功；修订回放不能重新下历史订单 |

### 不值得为了格式统一而重写的部分

小型资金曲线/日级表/季度模型输入、订单表、报表仍可用pandas。模拟Numba核已经使用数组，价值主要在核外准备和对象生命周期；没有证据支持重写成交数学。CSR与dense按实际稀疏率和消费者选择，不长期同时保留全部子策略的双份表示。

当前实际模拟和MODEL有不同的价格字段使用路径；本轮只指出接口迁移必须保留其各自口径，未认定某一路是错误，也未做公式修正。若后续希望统一，应另做语义审计，不能混入性能补丁。

## 建议顺序与性能验收

1. 本轮先完成17个因子的批量接口、旧signal/独立oracle对照和真实调度验证；不改core。
2. 候选：直接列式输出、有界因子结果交接；选币窄列排序与旧块释放。先保持现有S3及回调适配。
3. 候选：聚合v2与行情数组准备，分别验证后再连接。完整计时包含读取、转换、排序、进程启动、写盘、序列化、清理。
4. 候选：MODEL大矩阵交接；小型标签分析/订单侧仍保留pandas，避免低收益大重写。

以上2—4尚未实施，不能引用上一轮初始化19.4%作为这些改造或4050续算的收益。初始化、普通4050、修订回放、跨日/季度分别验收；继续沿用4c8g及既有Linux内存/swap约束，无新增尾行优化。
