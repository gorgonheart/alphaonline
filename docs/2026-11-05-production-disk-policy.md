# 生产磁盘与测试产物规范

本规范固化已确认要求；新增自动清理行为需单独实现与验证，不代表本文所有检查已自动化。

## 目录与所有权

- 生产服务器所有测试、对拍、微基准、采集样本、测试日志与缓存只能放各应用根目录的 `test/` 内。不得新增散落的research、benchmark临时输出。
- 整个test可人工删除，不影响业务功能。业务配置、有效snapshot、初始化联动请求、模型运行缓存、运行必需资源不得指向test；测试正在执行时删除test可中断该测试。
- 本地开发tests与文档可按仓库惯例维护；生产隔离验证入口从已提交Git重建测试源码，不复制生产密钥或账户配置。
- `data/server_initialization`和`data/model_replay`属于业务工作区，不属于可随意删除的test。沿用lifecycle的精确路径、账户锁、活跃进程排除和事务恢复顺序。
- 有效snapshot、S3、MODEL恢复点、账户交易记录、运行配置和业务回退源码不能作为普通临时文件删除。`.previous`与`.replay-previous`按现有安装/恢复协议处理。

## 每个新增落盘点必须说明

在设计/PR中记录：生产者、实际消费者、为何不能内存交接、路径归属、何时释放、失败/中断如何回收、保留上限。已有同等输入不得为了方便再保存一份完整行情或因子。

必须考虑硬链接：多个文件名不一定产生多份物理数据，但保留旧链接会阻止上游unlink后的空间回收。`du`逻辑大小不能简单相加；发布时还需要新文件临时写入空间，keep=1不等于峰值只占一份。

大表中间产物默认随任务释放；错误日志保留诊断即可，完整失败现场必须显式、有界、放test且无业务读取依赖。严禁默认完整采集每小时行情/snapshot用于调试。

## 清理性能要求

- 普通计算不新增递归du、全盘扫描、逐文件摘要或容量台账。
- 生命周期清理在最后消费者结束、退出或持锁恢复边界执行；无残留时只做小范围目录检查。
- 清理异常不覆盖计算异常；不得把提交后订单异常当成计算未提交。
- 真正删除记录总耗时与结果。评估优化包含读取、创建、复制、落盘、释放成本，不只测计算内核。
- 自动处理测试残留应只在验证入口或部署维护时触发，保护正在运行的测试，不把测试目录扫描加入交易轮次。

## 上线前专项复核清单

1. 列出本版新增/改变的全部写盘点，检查每个文件是否有消费者及释放时机。
2. 检查失败、强制退出后残留；覆盖同账户活跃任务与其他账户隔离，不仅测试成功删除。
3. 检查生产test可删除性，运行配置/业务导入不依赖test；验证入口可在删除后重建。
4. 检查应用日志、测试run、发布包及源码备份的保留策略；“可以手工删”不等于已有自动数量上限。
5. 以发布前后空闲空间、同轮临时峰值和失败后残留为证据；不为此复制全量市场数据。
6. 区分必要持久状态、可再生运行中间件、纯测试数据。无法证明安全的目录先列出归属，不做模糊通配删除。
7. 报告记录尚未自动化的检查和人工清理项，不将历史验收当成本版验证。
