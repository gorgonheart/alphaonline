# bStocks 自动识别：最小修改与人工复核

用户明确：手工 black_list 与 bStocks 独立，不把手工名单作为 bStocks 来源，不核对两者重复；bStocks 保留自动识别，不维护每小时历史。本轮不改变现有手工黑名单在框架中的作用，也不改变模型、回测计算算法。

## 修改范围

仅两个运行 tools 文件，core/startup 无功能取消或其他修改，因此本轮没有需要回退至原版的 core 代码。若以后取消 core 功能，仍应按用户要求优先恢复之前版本或 core 2.3.1 对应代码。

| 文件 | 修改 | 人工审核要点 |
| --- | --- | --- |
| `tools/prewarm_robust40.py` | 原自动刷新后，检查启用过滤的客户端是否有过成功获取记录 | 首次失败且成功时间戳为 0 时停止初始化；成功返回空名单有时间戳，允许继续；已有成功缓存的失败回退沿用原框架策略，不新增过期规则；关闭过滤及不支持 bStocks 的交易所保留原路径 |
| `tools/server_robust40.py` | `market_rules.pkl` 只保存现货/合约 `symbol_list` 与 `bstocks` | 去掉未使用的 min_qty、价格精度、最小金额、全币列表和 last_update，以及无必要的 deepcopy；Windows 初始化子进程继续读取同一文件；离线 fixture 禁止安装生产的检查保留 |

相比修改前只增加一次初始化阶段的成功时间戳判断，不增加网络请求、磁盘扫描、名单去重校验或历史存档。core 的 `fetch_bstocks_coins`、`apply_bstocks_black_list` 均未修改，原 API 重试、自动刷新及真实交易路径不变。名单来自原鉴权钱包配置接口；手工黑名单、账户配置不参与此次改动。此文件仍是本次初始化的输入副本，不是另一套人工名单。

不新增跨进程长期缓存：当前每个初始化进程依原流程自动识别，再将结果传给计算子进程。其后正常交易继续原自动识别流程。保留工作区成功清理、失败留存的既有行为；本轮未取消 ready 副本，也未改变日志或失败工作区清理策略。
