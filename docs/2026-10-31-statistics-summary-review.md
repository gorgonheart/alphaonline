# 统计通知补充：名称、历史极值与 UniMMR

用户要求子策略权重显示名称而非编号，账户总信息显示历史最高、最低和 UniMMR。本轮仅修改 `core/utils/statistics.py` 三处，共 +8/-1 行；不修改 startup、交易所客户端、配置、模型、实际下单或 alpha。与本轮开始保存的运行文件逐字节比较，仅此文件变化，之前未提交修改保留。

## 人工复核项

1. **子策略名称**：根据 `factory.config_list` 将权重 CSV 的零基数字列名映射为 `original_name`。无原名属性时使用配置名称，并去掉框架添加的 `S序号-` 前缀。仅更改通知文本，保留 CSV 列名、数值、列顺序和权重计算；不聚合重名策略，不将权重重新归一化。
2. **历史最高、最低账户总净值**：复用已读入并合并本轮的 equity.csv，计算不晚于本轮 run_time 的有效有限数值。包含本轮，第一次记录的高低值均为本轮值；不增加文件读取。该值来自本地保留记录，是账户金额极值，含出入金影响，不是经过资金份额调整的收益净值。
3. **UniMMR**：恢复到基础通知，不再要求 details=True；保留原查询函数、有限值校验和失败显示“未知”。每个统计轮次只调用一次 get_unimmr，基础持仓/净值先保存。notify=False 且 details=False 时只落盘，不为未发送的消息增加 UniMMR 请求；details=True 仍沿用原可选查询行为。

这不是 core 功能取消。名称映射、极值和 UniMMR 展示参照 core2.3.1 原报告功能恢复；没有整体恢复旧统计流程、旧历史成交重建、划转查询或旧错误成本展示。保留当前故障隔离和性能优化。

## 接口与性能

- 当前统一账户 overview 不包含 UniMMR，基础通知启用时新增一次客户端 get_unimmr 调用；底层既有重试可能产生多次 HTTP 请求，本轮不改交易所重试/超时。
- extrema 只在已经读入的权益列上做有限值过滤和 max/min；历史 CSV 仍读取一次。名称映射只处理最后一行及子策略列表，不读取子策略资金曲线或模型文件。
- 不新增其他账户概览、ticker、历史成交或划转查询。账户筛选、全部分钟 offset 和自动补 BNB 保持原行为。
- 普通账户/其他交易所现有客户端可能返回兼容默认值，例如 999；本轮沿用客户端语义，没有把接口可信性改造扩展到其他 core 文件。
