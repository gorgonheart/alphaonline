## 1. 1小时权益和价格影响：同一个窗口缺陷

三处共同使用单向窗口：`current_observed_at - 1h - 10min <= previous_observed_at <= current_observed_at - 1h`。

| 位置 | 问题 |
| --- | --- |
| core/utils/statistics.py:956附近 | 账户损益在权益CSV中按单向实际观察窗口选起点。 |
| tools/statistics_snapshot.py:43 position_history | 先过滤持仓字典，上一轮可能在转表前已被丢弃。 |
| core/utils/statis_func.py:133 get_historical_position | 转表后再次使用同样的单向条件；只修前一层仍然无效。 |

最新例子：上一轮run_time=09:55、observed_at=10:02:35.630518；当前run_time=10:55、observed_at=11:01:59.179186。真实间隔59分23.548668秒，上一轮观察比目标10:01:59晚36.451332秒，因此被排除。上一轮没有晚于本轮，完全可以用于“两轮之间”的对比。原规则把“晚于整60分钟目标点”误等同为不可用未来观察。

12轮中首轮确无基线；后11轮均有上一小时轮次，当前仅3轮命中、8轮误报。pnl_history.pkl中这8轮1h_status也是baseline_time=None/usable=False，故不只是通知文案问题。24小时缺基线在当前12小时数据下正常。

采用上一小时轮次、原数值公式重新计算最新两轮：

| 指标 | 原精度结果 | 当前整数展示规则 |
| --- | ---: | ---: |
| 账户实际权益差 | -66.86386266000045 USD | -67 USD |
| 期初现货价格影响 | -0.0336390723999973 U | 0 U |
| 期初合约价格影响 | -65.37694593077997 U | -65 U |

两轮按symbol排序后的持仓数量均相同。价格影响与权益差不是同一指标，仍可能有资金费、利息、费用、报价/观察时点及USD/USDT口径差异；本轮未对残差强行归因。现货价格影响接近零是真实小数被整数显示，不是修复后继续缺数据；遵守现有整数金额要求，不擅自改显示精度。

### 拟修改A：按轮次选基线，统一两种报告

1. 统一使用`run_time - 1h/24h`精确定位同账户、同offset、同来源/货币的目标轮次；仍使用真实`observed_at`展示实际起止和间隔。持仓继续要求原phase，空仓仍为有效记录。
2. 用相邻两轮已有实际值相减；不把观察时点伪造为整点价格，不插值、补历史或用相差两小时的最近轮替代缺失轮。
3. 仅接受基线观察早于当前观察；保留完整时间用于计算。观察间隔不足60分钟也可计算，文案说明实际间隔；这是按小时轮次统计，不声称精确60分钟市场窗口。
4. equity与持仓缓存采用同一轮次定位工具。修改position_history与get_historical_position两层接线，防止第二层重新过滤；独立旧调用没有提供run_time时保留原契约，不影响其他调用方。
5. 复用现有已加载字典，仅扫描小attrs并转最多两帧；不增加快照文件、API、全历史concat、哈希或新初始化。现有快照已有全部必要字段，无需重建。

## 2. 本轮成交额：干跑被错误显示为文件故障

`core/real_trading.py`在dry_run分支不调用`save_order_history`；`save_order_records`在没有有效FILLED/PARTIALLY_FILLED回执时也不创建文件。统计却总用`compute_recent_volume(strict=True)`读当月文件，因此PM2输出连续的`统计成交额不可用: .../order_history_202611.csv`。

当前55m没有本实例成交回执是已确认的干跑结果，不能为了统计而开启实际交易，也不能把目标下单金额当成交额。

另外两个原逻辑限制：该函数按run_time精确过滤，名称“最近1h成交额”与实际“本轮回执成交额”不一致；文件存在但无本轮时返回0，不能区分零成交和缺记录。NEW/GTC即时回执未成交会被排除，后续成交没有自动回查，所以当前数据源也不能承诺完整交易所1小时成交额。

### 拟修改B：保持现有数据源，准确表达覆盖范围

1. `statistics.run`把本次已加载的运行模式显式传给账户摘要；dry_run显示`本轮成交额：0（干跑未下单）`，含义仅限本实例，直接跳过订单CSV读取及缺文件异常日志。其他实例/手动成交不在这个0的范围内。
2. 正式模式有回执时显示`本轮回执成交额`，使用原实际executed_qty/quote_qty；不读取逐笔或历史接口。
3. 正式模式文件不存在、无法读取或没有本轮记录时显示`本轮回执未记录`，不冒充0；有回执也只表示已记录部分，不能据此断言所有挂单完成。
4. 不新增订单完成凭证、逐笔采集或交易端写入；不修改real_trading、BN下单/补BNB及模式配置。未来如必须证明“正式零成交/订单已全部完成”，需另外审核最小交易结果接线，本批不擅自扩展。

## 3. 现货成本：缺少建立机制，运行时长不能解决

`core/utils/statis_func.py:30 calc_spot_position`明确写死change/pnl_u/avg_price为NaN、cost_status为待对账。此前修复停用了存在数量错误的旧成本，没有实现新可信成本的初始化和续算。这一点必须直说，不能解释为“再等几轮就有”。

PM余额和当前行情能提供数量/市值，现有统计接口不提供现货可信买入均价。即使忽略手动买卖/转账，相同小时末持仓也可来自不同买入价或小时内买卖；小时持仓本身不能唯一确定成本。比如都持1币、现价100，买入成本80与120，对应浮盈分别20与-20。

### 拟修改C（建议本批）：让已有小时数据有用，成本未知明确保留

- 使用A已定位的基线计算现货`price_change_1h = current_price / previous_price - 1`；价格影响复用`opening_price_impact_1h = previous_qty * (current_price - previous_price)`。列名明确1h口径，绝不填入原avg_price/pnl_u/change冒充持仓周期数据。
- 当前已存在的所有现货缺少可信期初成本，`cost_status`改为明确的`缺少期初成本`；持仓展示不再固定铺开三个永久空成本列，有真实可用成本时才展示。原持久化字段暂保留兼容，不写假值。
- 无基线/新出现币种的1h指标仍未知；已退出币种保留在价格影响报告中，不伪造当前持仓。
- 公共绘表工具、合约展示和合约BN原生成本不改；仅当前现货展示构造时选择列。百分比和金额沿用既有格式，无千分位。

如果本次目标包含“当前11个老现货必须恢复真实avg_price/pnl_u”，A/B/C仍不足，需要可信期初成本或放宽“不补历史”约束。本批推荐不恢复错误旧CSV、不用现价初始化成本。未来可从已知空仓后的新持仓周期开始，按每小时实际成交汇总建立2.3.1的净投入/回本价/持仓周期损益；这需要完整的买卖额、数量与费用，不能仅由持仓快照推导，且不等于剩余持仓均价/未实现盈亏。该记账扩展另行审核，当前未实施。
