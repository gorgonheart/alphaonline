# 因子代码双机对照与发布评估（2026-11-06）

## 结论与范围

用户授权将实际测试代码放到正式机 `test/` 反向验证。两台机器均已完成实际版本的同机、同输入对照；没有复现“正式代码固定快约20秒”的稳定关系。正式机两组完整因子输出精确一致，测试代码自身CPU用量未增加。但是正式机实验与其他服务并发、发生明显换页，不能据此宣称两版墙钟性能严格等价，更不能承诺测试代码上线后固定快20秒。

**因子阶段现有证据不支持以20秒代码回归为由阻止性能改动进入发布候选；当前测试目录不能整包直接覆盖正式目录。** 全版核查另发现未同步的恢复点修正和上游联动配置差异，见下文。此次仅诊断、隔离测试与记录，没有发布、重启、改账户、交易状态或通知。

两组均为87份文件，逐文件内容完全相同（不设浮点容差），包括存储行序与缺失值。未只比较末行或汇总权重。正式机因子输出验证不替代截面、S3、MODEL、目标订单完整链路。

## 3. 与测试机结果合看

此前测试机同输入完整进程：测试82.548/85.938秒，正式81.604/92.606秒；正式模块未稳定快20秒。详细边界见[因果审查](2026-11-06-factor-block-causal-review.md)。本次正式机使用另一轮冻结输入、不同机器和同期负载，**不能把测试机82秒与正式机120秒直接作跨机硬件对比**。

两端当前32个时序因子依赖都有多参数接口且AST相同，4个截面模块使用自己的接口。正式与测试因子主路径的实际差别主要是聚合统计，不是测试遗漏signal_multi_params。测试版未恢复此前端到端无收益的市值倍率候选。

准备前移单独验收：账户预选、ready稳定等待3→1秒位于因子阶段外；不会解释FACTOR_BLOCKS自身差值。12:25自然轮测试因子慢约31秒，但计算下单信息标记仅晚约2秒，涉及提前开始和执行器缓存等多个因素，不能全归因准备前移。

### 4.1 Arrow机器配置不能照抄

测试实际 `ARROW_DEMAND_ENABLED=True`，正式alpha2尚无需求协议模块，当前发布全长。此次性能候选可保留正式上游全量、交易端需求开关False，不要求同步尚未验收的alpha1.1.12映射/价量改动。如果要一起启用按需缩短，则另列上游匹配协议与机器配置，不能只开启消费者。初始化全量、普通读取至少5000且最终4050的约定不变。

### 4.2 两端共同存在的恢复点遗漏

两端实际均 `CHECKPOINT_POINTS=25`，且子策略选币列变化时丢弃历史恢复点。本地已有的修正未部署到两端：

1. 24小时前那根K线发生修订，需要它**严格之前**的状态；包含当前边界需26个小时恢复点。
2. 新增选中币种时，按币种对齐旧lots/target_lots/last_prices，保留旧币单位和旧状态；新增币之前持仓为0。删除币或单位变化仍拒绝不安全对齐。

隔离递进证据：实际候选在24h边界测试失败；只改26仍因扩币丢恢复点失败；叠加本地 `core/equity.py` 与 `core/utils/checkpoints.py` 后，相关24项通过，含真实模拟器资金费修订回放与从头计算精确一致。

这是两端共有旧问题，不是本次因子统计引入的回归。建议在整版发布前将这两个core文件和已有配置修正纳入人工复核。扩大保留数不会凭空补出已丢失的历史点；现有snapshot逐轮积累，确实无点仍走已批准的后台重建流程。

## 6. 发布判断与后续最小步骤

1. 性能调查已完成双机互换和正式全市场严格输出对照；不再为寻找固定20秒重复大规模实验。保留现有因子统计，不因这次对比修改并发、GC或数学。
2. 当前测试目录**不建议原样发布**。制作范围受控的交易端候选：保留生产账户/代理/资源参数，Arrow需求关闭；纳入已独立验证的26点及扩币对齐修正并列出两处core人工复核。
3. 发布前核对组装候选与本次验证文件一致，补与最终组装变更直接相关的回归。既有生产状态保留；不以复制代码重跑同一交易时刻。
4. 经用户发布授权后按合法offset检查JIT缓存命中、完整计算与订单阶段、状态提交和下一轮恢复点；不承诺自然轮固定节省20秒。本轮不执行发布。
