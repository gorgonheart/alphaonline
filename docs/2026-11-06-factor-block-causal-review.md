# Factor block：同机对照、接口核对与计时边界

本轮只读核查正式服务器，并在测试服务器的 `alphatrade/test/factor-causal-20261106/` 运行隔离实验。未替换业务模块、重启服务、修改账户或上游调度。网络审计钩子禁止实验访问交易接口。本文记录诊断证据，不代表新的性能补丁已经发布。

## 1. 当前策略没有遗漏多参数接口

直接读取两端当前账户依赖及服务器文件：32 个时序因子模块（含间接引用）均有 `signal_multi_params()`，AST 一致。保留 `signal()` 是兼容旧调用，并不表示当前框架选择了旧接口；`core/factor.py` 优先调用多参数入口，已发布的预计算列另行直接使用。

4 个截面模块是 `动态回撤阈值`、`固定回撤阈值触发币数占比开仓门槛`、`TopKTo2K`、`VolumeMaxBias_进出场阈值分离官方`，其 `signal()`/块式接口属于截面协议，不要求改成时序的多参数入口。两端全库都有 25 个仅旧接口文件，但不在当前账户依赖中。

## 2. 前移准备与因子耗时必须分开统计

已核对两端实际 `startup.py`，不是只看本地代码：

| 项目 | 测试服务器 | 正式服务器 |
| --- | --- | --- |
| 本轮账户 offset 筛选 | ready 等待前 | ready 后逐账户判断 |
| MODEL 轻量状态预检 | ready 前 | 原本也在 ready 前 |
| 公共 ready 齐全后的稳定等待 | 1 秒 | 3 秒 |
| trade worker 启动、账户资产准备 | ready 后 | ready 后 |
| 同轮行情修订检查 | ready 后 | ready 后 |

此次前移并未实现整个交易 worker 的提前预热，更没有提前查询余额、补 BNB 或下单。当前批准的第一步本来就只包括账户预选和公共等待。修订检查需要本轮完整行情，不能把它整体移动到 ready 前。

因子阶段提前约 8 秒开始，不能全部归因于账户预选；上游发布时间、机器、前置检查也不同。测试因子阶段慢约 31 秒，却不代表交易计算最终慢 31 秒。目标计算缓存等后半程差异抵消了部分延迟。最后两个时间标记只有整秒精度；测试是 dry_run，不能比较真实订单完成时间。

测试四份 ready 观察到因子阶段开始约 20.293 秒。其中 dispatch 到 account_entry 为 14.919 秒，不能全部视为可以提前的导入开销：该轮 `MODEL_REPLAY.prepare_s=8.693009`，包含同轮修订输入读取 7.013600 秒、比较 0.939353 秒；旧状态读取 0.451205 秒、pending 写入 0.323589 秒另有记录。没有为剩余部分强行分摊。

后续统计固定三个边界：① 因子阶段独立耗时；② ready 观察到计算下单信息；③ 合法 offset 到计算下单信息。CPU 秒单独记录。不能把“本次循环开始”到结束当纯计算时间，因为其中包含提前唤醒和等待；不能把并行 worker 累计墙钟加到父进程墙钟上。

## 3. 实际正式模块在测试机运行

使用实际服务器取回的正式因子主路径模块覆盖隔离源码，与测试模块共享同一冻结的 11:25 Arrow、市值、BTC、配置顺序、4 个 worker、32 币分片、2016 小时块。实验进程 nice=12，不限制业务进程。完整进程时间含导入、spawn、因子计算、传输、写块、释放及退出；不包含之前一次性冻结准备 2.394 秒，也不代表完整交易流程。

| 顺序样本 | 完整因子进程 | 进程树 RSS 峰值 | 同期全机 user CPU 秒（不含 nice CPU） |
| --- | ---: | ---: | ---: |
| 测试模块 test1 | 82.548 秒 | 1.669 GiB | 4.03 |
| 正式模块 prod1 | 81.604 秒 | 1.656 GiB | 4.72 |
| 正式模块 prod2 | 92.606 秒 | 1.667 GiB | 37.38 |

正式模块在同机并未稳定快出原先两机的 20 秒。较慢样本伴随更多其他进程 CPU；这是关联证据，不能把系统计数精确归因到单个进程。RSS 是采样的进程树值，不包含完整页缓存，不可当成 cgroup 内存峰值。

另做完整输出对拍：**924 个任务、3,681,943 行、81 个存储列、87 份 IPC 块严格一致**（先逐文件字节比较，必要时逐值精确断言，无浮点容差），覆盖全部存储行序与缺失值。参考块已释放。此次公共市场离线缓存额外纳入 283 行 `PREDICTUSDT`，比 11:25 自然轮多 1 个任务；两版实验的集合完全相同，但不能将实验称为自然轮集合的逐币复刻。没有运行整套模拟／S3／MODEL／订单对拍，不能用因子结果替代它们。

## 4. 已排除和保留的假设

- 两端当前 Arrow schema 列名／dtype 相同；因子 worker 均走 `arrow_strict`，先保留至少 5000 行，再按框架规则保留 4050。不能说两端行情数值因此必然相同；只是排除本轮列宽和接口分支差异。
- 抽查两端 BTC/ETH/OP/PUMP/ETC/1000CAT 市值辅助文件，行数、文件大小及七个数值列 dtype 相同；BTC 辅助输入均为 14060 行。没有发现测试服仍使用字符串数值列的证据。
- 924 任务详细诊断中，市值和 BTC 各调用 924 次，不是每币重复 2–4 次市值读取。全部 pickle 读取累计约 1.957 CPU 秒；市值因子含外部处理约 29.446 CPU 秒，其中大部分不是磁盘 unpickle。
- 该诊断 ZfMeanQ 约 29.226 CPU 秒、Cci异常隔离约 23.524、111输入隔离约 16.993、CorrBTC 含外部数据约 16.294、BiasV1 约 13.626，pandas→Polars 约 14.996。存在嵌套，不能把外部数据再加一次。8 个抽样任务带 cProfile，这些数值用于定位而非最终性能验收。
- 市值倍率处理会影响 `circulating_supply` 的单位，当前市值因子实际依赖供应量，不能因名称为市值就跳过倍率修正。此前未达到端到端收益标准的候选仍未恢复到业务代码。

## 6. 上游重叠与后续决策

12:25 自然轮因子阶段 12:26:59.540 开始，alpha 在 12:27:00 开始合并 spot/swap 5m，分别于 12:27:11／17 结束，存在真实重叠。同轮测试 worker 累计 CPU 253.076 秒／墙钟 335.688 秒；较低干扰隔离基准为 242.139／279.251 秒。不能把这两组差全部归因于重叠：尚有页缓存、输入集合、宿主负载及进程优先级差异。

固定输入补充一组时间窗口实验，未改变 alpha 配置：12:45:05 在上游生产过程中开始，12:49:00 在主要预处理／5m 合并结束后开始。

| 项目 | 上游生产重叠窗口 | 主要生产结束后的窗口 |
| --- | ---: | ---: |
| 完整因子进程 | 136.950 秒 | 92.576 秒 |
| FACTOR_BLOCKS | 113.776 秒 | 86.817 秒 |
| worker 累计 CPU | 250.409 秒 | 244.649 秒 |
| worker 累计墙钟 | 405.083 秒 | 312.762 秒 |
| 父 partition + write 墙钟 | 18.127 秒 | 13.830 秒 |
| 进程树 RSS 峰值 | 1.705 GiB | 1.686 GiB |
| 全机 swap out 增量 | 838.14 MiB | 0.016 MiB |

同代码同输入，环境重叠可以造成数十秒波动，且连导入／启动等阶段外成本也会扩大。后一个窗口仍有 alpha 主进程及其他进程活动，不能称完全空闲。监测进程自身也消耗 CPU，已包含在整机资源统计中。

限制：这是低优先级 nice=12 的实验；两端实际 trade 策略均为 nice=3。实验重叠了完整上游生产，而自然因子阶段主要重叠后续 5m 合并；**不能把 44.374 秒或 26.959 秒直接当作自然轮可节省时间**，也不能证明推迟因子开始会更早下单。45m 上游在实验期间正常完成，但 spot/swap 预处理分别耗时 66.3／90.6 秒，说明重叠会反向影响上游，不应仅以交易进程单项利用率决定提前并发。

本轮决策：不把测试服较慢归结为遗漏参数接口；不按一次样本提高 pending；不直接修改上下游优先级、推迟行情合并或提前重计算。已取得实际正式模块同输入严格等价证据，但原来两机 20.81 秒尚不能精确逐秒归因。下一步应先用自然因子窗口的小型进程／IO 采样确认上游合并贡献，再对最高 CPU 热点开展单项严格对拍；现有统计不需要另建长期行情副本。准备前移的验收使用第 2 节的完整时间线，因子单项优化不能替代整轮交付延迟。
