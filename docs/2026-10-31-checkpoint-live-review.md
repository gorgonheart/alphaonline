# MODEL 共同恢复点接入与人工复核

状态：代码已接入服务器 worker；只做离线验证，未启动/重启实盘，未下单或通知，未安装/删除生产 snapshot。alpha 无修改。本文替代《checkpoint-trial》中“尚未接入”的实现状态；其离线测量仍只是内核测量。

## 行为

- MODEL worker 设置 `checkpoint_hours=25`；`incremental_lookback_hours` 仍必须为 0。传统账户默认 checkpoint_hours=0，原有 lookback 功能保留。
- 每根已计算小时保存一个小状态，保留最近25点（含当前点），因此能恢复到最近24根被修订K线之前；不是保证任意24小时停机都能回放。共同点必须同时存在于14个子策略、两个再择时账户、S3、9个专家和最终 MODEL 账户。
- 正常每小时合并、淘汰旧点，不复制整份历史；数组币种布局改变时丢弃旧布局的小状态，重新积累，避免把相同位置的数组当成相同币种。
- 交易 worker 在账户/交易所操作之前比较最近168小时的基础行情、成交量、交易资格及映射、Pivot模拟输入。Arrow先裁列裁行，再转pandas；不新增哈希。无修订则原增量路径继续。
- 有修订时选严格早于最早修订时刻的共同点。在本账户隔离工作区恢复子策略两类账户、选币、ratio、S3持仓/延迟rank队列及输出、MODEL历史和训练状态，再运行框架原计算流程。S3日期不变。
- 采用既有账户锁和 `complete` 提交标记。恢复文件先在隔离副本处理及核对；运行期间原完整包保留在 `.replay-previous`。只有目标聚合对拍、共同cutoff验证通过才写 `complete=True`。计算异常还原原包，失败现场留在 `data/model_replay`。进程被杀后下次协调器恢复原包；已提交后交易所异常保留新计算，避免回退可能已执行的目标。
- 成功事务把旧完整包移到现有 `.previous` 槽位，只保留一份完整备份；`clean_start=True` 继续保留 MODEL 包和相应备份。
- 超出恢复点、币种布局无法匹配、输入覆盖不足等情况沿用自动完整初始化。旧包缺少 checkpoint 协议，不做转换，下次正常调度会要求初始化；没有在本次开发中清理旧数据。

## 明确边界

最近168小时检查不是无限历史审计。早于该范围的修订、外部市值/BTC辅助源历史修订和预计算公式版本变化，不能宣称都能自动定位；已知这类变更应完整重建。MODEL现有重叠/配置/单位检查继续保留，不能把无法解释的差异自动覆盖。

恢复点不是独立完整备份。要保留现有 snapshot 历史、当前4050输入的因子预热区间及所需外部源。首次140xx初始化和短窗口Arrow的依赖约束保持，不修改参数，不开启Tail-Only。

事务保护范围是 snapshot 内的计算状态；框架派生回测CSV和运行缓存仍按原方式生成，失败后重算，不提供跨进程统计读者的原子可见性。原账户刷新、自动补BNB、撤单顺序保留；不补发任何历史订单，当前目标通过原校验后才进入正常目标下单步骤。

每轮覆盖写的是 `lots_state*.pkl`（含有界队列）、S3截面pkl（4050小时输出+小状态队列）、`model/state.pkl`（完整必要历史+10个账户恢复点）、`model/revision_inputs.pkl`（最近168小时输入）。不是每小时新增一个完整目录；`revision_inputs.pending.pkl`仅是本轮待提交输入。
