# 历史修订恢复点：离线实现、5m/15m 对照与开销评估

## 本轮结论与边界

已实现可运行的离线试验：MODEL 小状态检查点及修订重放、S3 小状态检查点及修订重放、共同截止时间选择、季度模型复用。全部为显式调用；现有 calculate/advance 默认 checkpoint_hours=0，原交易入口没有传入新参数，正常实盘行为保持。当前 startup 遇到不一致状态仍走原完整初始化，不会自动使用本试验。

本轮新增功能不修改 core、startup、config、accounts、sections 或 alpha。没有取消原保护、放宽价格容差、恢复生产状态、启动进程、下单、通知或联网访问交易所。已有未提交工作保留。所有试验写入 research/checkpoint_trial。

用户选择的目标是匹配最新修订数据的完整回测。试验验证了各状态模块的恢复机制；尚未完成从因子/选币到 S3、全部子策略和 MODEL 的统一生产事务接入，不能把本轮结果视为全策略端到端实盘验收。

## 搜索依据与采用方式

- [Flink 检查点和大状态调优](https://nightlies.apache.org/flink/flink-docs-master/docs/ops/state/large_state_tuning/)：检查点频率、保留数量和恢复成本需要一起考虑。本项目采用有限数量的小状态，不复制整套市场与结果历史。
- [Flink 增量检查点说明](https://flink.apache.org/2022/05/30/improving-speed-and-stability-of-checkpointing-with-generic-log-based-incremental-checkpoints/)：保存耗时与重放耗时存在取舍。本轮仅借鉴原则，不引入 Flink、RocksDB、日志系统等基础设施。
- [Google MLOps 训练触发与验证](https://docs.cloud.google.com/architecture/mlops-continuous-delivery-and-automation-pipelines-in-machine-learning)：训练触发与数据/模型验证分离。季度模型只有实际训练输入、标签和管道配置相同才复用，未以原始价格容差判断。
- [Feast 时间一致性](https://docs.feast.dev/getting-started/concepts/point-in-time-joins)：区分事后修订与当时已知。用户本次选择最新修订口径，模拟历史允许重算，实际成交不回滚、不补发。

## 实现细节

MODEL 恢复点仅保存每个专家及最终账户的资金、当前手数、待执行手数、最后结算价格、初始化标记，附币种及单位布局。历史行情和完整结果仅保留原有一份；恢复时截取原结果的有效前缀，重新计算后缀。新日到来时正常重算日度观察，训练样本被修订的季度重新训练；未变化季度复用管道。没有强行保留受修订影响的季度模型。

S3 的检查点保留 cutoff、held、ranks、initialized、params/version；output 仍仅一份，不在每个点复制约135MB的4050小时输出。按小时推进时，历史 output 的合并只在末尾做一次。原始 VolumeMaxBias 及选币算法不变，空截面和延迟排名沿用原函数。

common_before 只负责同一账户/offset各模块时间点的交集；调用方仍必须提供已验证的同账户数据及最早受影响时间。试验没有自动推断历史所有修订范围，没有跨币种映射迁移，没有将旧生产包自动升级为带检查点的包。

本轮参数24表示保留最近24个小时结束点。修订必须严格晚于所选恢复点；不能保证最早保留点自身发生修订也能恢复。若生产要求完整24小时修订覆盖，应考虑保留25个边界点，并以实际时间检查覆盖。超范围须明确转更早状态/完整重算，不静默沿用旧历史。

## 真实40m修订验证

使用保存的2026-10-31 03:40 UTC MODEL状态，以及上一轮记录的149个close差异：

- 原价格完整模拟与已保存结果逐值一致。
- 重新建立最近24个小状态后，从00:40 UTC恢复，重放01:40至03:40。
- 9个专家及最终账户的曲线、最终手数、待执行手数和结算状态均与修订价格下的完整模拟一致。
- 本次 parent/base/delta 与原记录相同，季度训练未被触发。

这里固定了已保存的子策略输入/权重；没有重算上游因子和选币，没有推进至原失败轮次要求的06:40。因此它验证真实价格修订的 MODEL 恢复，不等于整套最新行情回测对拍。

## MODEL与S3开销

最终数据：research/checkpoint_trial/final_model.json。以下是本机离线测量，不含市场读取、因子重算、选币、网络及交易。

| 项目 | 结果 |
| --- | ---: |
| 10个MODEL账户完整历史模拟（编译后） | 10.407秒 |
| 同样模拟并采集最近24点（编译后） | 10.749秒 |
| 初始化采集额外计算 | 约0.342秒 |
| 正常单小时采集额外计算，10账户合计，5次中位差之和 | 约4.4毫秒 |
| 24点MODEL状态序列化 | 约26.6毫秒 |
| 研究文件写入 | 约2.0毫秒 |
| 本次真实三小时MODEL重放 | 约1.97秒 |
| MODEL 24点含布局的pickle大小 | 3,392,991字节 |

首次原模拟含Numba编译约27.64秒；首次检查点分段调用约10.29秒，含新resume参数类型的编译，所以不能直接拿冷启动与热运行相减。写入计时可能受Windows页缓存影响，不是持久刷盘时延保证。

S3使用真实保存状态及563币规模，合成未来24小时排名作性能负载（并非伪造实盘行情）：原函数批量续算5.759秒，新试验2.671秒，持仓和输出相同。加速来自合并一次历史output，而非改变公式。24点额外388,864字节。该时间不包含上游VolumeMaxBias因子计算，也不是实盘全链路性能保证。

季度训练：真实4个模型全训练约116.96毫秒，复用约94.54毫秒，fit次数4→0，预测逐值相同。因此本项目的主要收益是避免子策略/模拟账户全历史重算，不是节省小型Logistic模型训练。复用路径的比较本身也有成本。

## 存储估算

当前40m目录约972.61MiB。恢复点无需复制这套目录：

| 组成 | 最近24点额外存储 |
| --- | ---: |
| 9专家+最终MODEL账户 | 3,392,991字节，实测 |
| S3 | 388,864字节，真实状态规模的试验实测 |
| 14子策略、含再择时共16个模拟状态 | 2,389,944字节，单点99,581字节×24估算 |
| 合计 | 6,171,799字节，约5.89MiB/账户 |
| 11个同规模MODEL账户 | 约64.74MiB |

这是每个offset一个MODEL账户的估算；多个账户不能共享策略恢复状态，应按账户累加。固定保留点数后不按运行小时无限增长。尚不包含生产事务重放的临时空间；如果直接复制当前完整目录作工作区，单账户仍可能临时需要接近1GiB，所以正式接入要单独设计输出替换，不能把65MiB误认为全流程磁盘峰值。

## 5m、15m传统策略对照

当前实际账户：5m-onheart1020、15m-nheart1020；均为HybridRotationDriftStrategy、14个子策略，默认section_state=False。两者S3均为(720,0.1,0.9,2026-08-30)，走原全量signal路径，并非MODEL的显式S3状态协议。

以各自真实已保存权重、市场价格、模拟单位及手续费，取240小时进行原core模拟内核测试：

- 0与24捕获选项下，无修订时28个子策略的结果完全相同。
- 各子策略对有持仓的近期一根close注入1%修订，恢复点重放全部匹配该区间的完整重算。
- 每个账户13/14个子策略在不回放时出现历史权益差；未修改真实价格或状态。
- 另对两账户各S1、S3执行实际calc_equity入口，包括离线文件读写、恢复队列、结果截断与重存，4项均匹配完整重算。

| 指标 | 5m | 15m |
| --- | ---: | ---: |
| 14子策略24点存储 | 1,330,924字节 | 1,327,468字节 |
| 本次捕获额外耗时（单次，存在测量噪声） | 约0.4毫秒 | 约3.8毫秒 |
| 重放约24小时，14子策略合计 | 0.124秒 | 0.123秒 |
| 仅追加1小时，14子策略合计 | 0.006秒 | 0.006秒 |

仍固定选币和再择时输入，不能外推成“打开24后整轮实盘只增加0.12秒”。时序/截面因子、选币留存窗口、再择时以及本地文件读写都可能增加成本。此测试验证当前窗口内修订恢复；不是从策略最早起点完整重跑的验收。

## incremental_lookback_hours是否值得启用

**有价值，但不应现在直接改全局值。** 对传统策略，它已经能以很小的模拟成本纠正近期行情修订造成的资金曲线偏差；它是每轮固定回退，不是检测到修订才回退。是否使用6/12/24取决于希望覆盖的修订年龄，不能只看停机时长。

当前两个重要约束：

1. config.py账户allowed_attrs尚不包含incremental_lookback_hours；单独在账户中写24目前不会生效。config.json则可覆盖全局值。后续需明确账户优先级，才能仅对5m/15m启用。
2. MODEL的server profile和section_state均禁止非零；全局改24会使MODEL账户启动失败。原保护不能直接删除。

建议保持当前生产全局0；传统5m/15m在账户级配置接入、选币/再择时回放对拍后分别启用。MODEL可采用工具层先恢复到共同snapshot，再保持内部lookback=0向前续算的方案，优先避免改core回退语义；这是下一阶段设计，尚未接入交易入口。

## 测试与后续生产接入范围

TDD先出现缺失replay模块，再修复测试中的空观察及Pandas内部缓存比较问题。主合同/runtime/试验53项通过；补充恢复/隔离33项通过，旧账户路径缺失50项跳过，不计通过。当前实际5m/15m已另加策略加载及真实calc_equity验证；最终试验与当前账户专项15项通过，无跳过。日志见research/checkpoint_trial。

正式启用前仍需完成：共同恢复点的持久化与完成标记；修订范围自动定位；子策略/S3/MODEL统一恢复与失败隔离；因子重算及Arrow输入一致性；包括再择时的全链路最新修订回测对拍。跨币种/单位变化目前明确拒绝，超出历史覆盖仍需更早状态或历史。不得把试验函数直接接入下单路径并吞掉这些条件。

本轮没有core/startup功能变更需要恢复原版；正式接入若涉及共享接口，另列最小修改并人工复核。没有实际改变正在运行的5m、15m、20m、40m、55m配置或状态。
